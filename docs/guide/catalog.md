# 全书目录

本书按知识依赖分为六卷。章节编号对应推荐阅读顺序；你也可以从熟悉的业务问题进入，再补读前置机制。

本版新增 [贯穿项目：支付告警 Copilot](/project/overview)，包含完整 Python/Java 源码、本机启动、Memory 实战、部署设计与故障演练。27 章均补充了项目落地分析。

## 第一卷 · 模型与 Agent 内核

先理解模型如何产生输出，再把一次调用组织成有预算、有状态、有验证的执行循环。

### [01 · 岗位地图与问题定义](/chapters/01)

先明确要交付什么，再决定需要多少智能。你的后端经验会在权限、可靠性与系统集成上形成优势。

重点：职业、岗位、需求、workflow。约 3,008 字；14 分钟精读。

### [02 · LLM 原理与必要数学](/chapters/02)

学到能解释模型为什么这样表现，并能做工程决策；算法岗位再继续深入推导。

重点：token、Transformer、数学、embedding。约 2,825 字；13 分钟精读。

### [03 · 模型选型、提示词与结构化输出](/chapters/03)

选择模型要看你的任务分布；提示词、工具合同和验收器要共同工作。

重点：prompt、schema、选型、routing。约 2,791 字；13 分钟精读。

### [04 · Context Engineering：每轮让模型看到什么](/chapters/04)

上下文是一个有预算的数据包，需要选择、压缩、排序和更新。

重点：context、压缩、prompt caching、token。约 2,925 字；13 分钟精读。

### [05 · Tool Calling 与业务工具设计](/chapters/05)

模型提出调用请求，应用负责校验、授权、执行并返回结果。

重点：function calling、工具、幂等、权限。约 2,800 字；13 分钟精读。

### [06 · Agent Loop、规划与停止条件](/chapters/06)

一个可控的 Agent 是有状态、有预算、有工具和可验证终点的决策循环。

重点：ReAct、planning、reflection、harness。约 3,212 字；14 分钟精读。

### [07 · 状态机、Checkpoint 与持久化运行](/chapters/07)

将一次对话升级为能暂停、恢复、审计的任务。

重点：state、checkpoint、durability、恢复。约 3,092 字；14 分钟精读。


## 第二卷 · 记忆与知识系统

区分状态、记忆与缓存，设计可更新、可删除、可追溯的知识与信息供给系统。

### [08 · Memory 全景：状态、记忆、知识与缓存](/chapters/08)

先区分“存了什么、为谁存、何时读、谁能删”，再考虑向量数据库。

重点：memory、短期记忆、长期记忆、KV cache。约 2,966 字；13 分钟精读。

### [09 · Memory 工程：写入、冲突、检索和遗忘](/chapters/09)

一条记忆应该能被追溯、纠正、过期和删除。

重点：memory、TTL、冲突、遗忘、多租户。约 2,929 字；13 分钟精读。

### [10 · RAG 数据工程：从文件到可引用证据](/chapters/10)

RAG 的下限由数据质量、更新链路和权限元数据决定。

重点：RAG、chunking、OCR、数据管道。约 2,817 字；13 分钟精读。

### [11 · 检索系统：Hybrid、Rerank 与搜索评测](/chapters/11)

检索要同时照顾语义表达、精确标识、权限和排序质量。

重点：BM25、HNSW、rerank、hybrid、GraphRAG。约 2,794 字；13 分钟精读。


## 第三卷 · 协作、协议与业务

让模型连接受控工具，把 Agent 接到 Python、Java 与现有企业服务。

### [12 · Workflow 与 Multi-agent：组织多个决策单元](/chapters/12)

多 Agent 的价值来自分工、隔离与并行，收益必须超过协调成本。

重点：multi-agent、DAG、handoff、协作。约 2,745 字；12 分钟精读。

### [13 · MCP、A2A、Skills 与框架生态](/chapters/13)

理解协议边界，避免把连接标准误当作完整 Agent 平台。

重点：MCP、A2A、skills、LangGraph。约 2,715 字；12 分钟精读。

### [14 · Python Agent 服务：异步、类型与测试](/chapters/14)

把实验脚本变成边界清晰、可运行、可维护的后端服务。

重点：Python、asyncio、FastAPI、testing。约 2,679 字；12 分钟精读。

### [15 · Java / Spring 业务系统如何接入](/chapters/15)

保留你熟悉的后端能力，把模型放在受控的业务边界中。

重点：Java、Spring Boot、Spring AI、事务。约 2,757 字；12 分钟精读。

### [16 · 服务层：API、流式输出与长任务](/chapters/16)

用户交互、后台执行和真实业务动作需要分开建模。

重点：SSE、WebSocket、队列、API。约 2,701 字；12 分钟精读。


## 第四卷 · 平台与推理 Infra

从队列、存储、租户隔离到 GPU 与 KV cache，理解系统承载能力。

### [17 · 数据与平台 Infra：租户、存储与隔离](/chapters/17)

基础设施的任务是把一次成功演示变成可持续服务。

重点：infra、多租户、PostgreSQL、sandbox。约 3,127 字；14 分钟精读。

### [18 · 推理 Infra：GPU、KV Cache 与吞吐](/chapters/18)

应用工程师要理解性能来源；推理岗位需要进一步实测与优化底层系统。

重点：GPU、vLLM、KV cache、batching。约 2,996 字；14 分钟精读。


## 第五卷 · 质量、安全与交付

用任务终态衡量质量，在故障、攻击、版本变化与成本约束下交付系统。

### [19 · Evaluation：把“感觉不错”变成证据](/chapters/19)

Agent 的质量要看真实结果、轨迹、成本与风险，不能只看一段回答。

重点：eval、judge、pass@k、benchmark。约 2,900 字；13 分钟精读。

### [20 · Observability 与成本：从一次失败追到根因](/chapters/20)

把运行事件、模型行为和业务结果连接起来，才能优化。

重点：AgentOps、trace、成本、p95。约 2,760 字；12 分钟精读。

### [21 · 可靠性、部署与发布工程](/chapters/21)

模型不确定性之外，分布式系统的老问题一个也不会自动消失。

重点：Docker、Kubernetes、CI/CD、SLO。约 2,864 字；13 分钟精读。

### [22 · 安全：提示注入、工具权限与沙箱](/chapters/22)

安全边界需要代码和权限机制执行，不能只依赖模型听话。

重点：security、prompt injection、sandbox、安全。约 2,804 字；13 分钟精读。

### [23 · 数据治理、隐私与企业交付](/chapters/23)

企业落地还要回答数据从哪里来、去哪里、保存多久、谁能查看。

重点：治理、隐私、审计、合规。约 2,824 字；13 分钟精读。


## 第六卷 · 进阶、产品与求职

补齐训练、多模态与人机协作，把学习成果变成可审查的作品集。

### [24 · 微调、偏好优化与 Agent 学习](/chapters/24)

先用评测定位问题，确认训练能解决，再投入训练成本。

重点：SFT、LoRA、DPO、RL、训练。约 2,761 字；13 分钟精读。

### [25 · 多模态、浏览器与 Coding Agent](/chapters/25)

当工具能看屏幕、操作网页或执行代码，验证与隔离更重要。

重点：multimodal、browser、coding agent、语音。约 2,699 字；12 分钟精读。

### [26 · 产品体验与人机协作](/chapters/26)

可靠的 Agent 产品让用户理解正在发生什么，并能在关键位置接管。

重点：UX、HITL、product、人工接管。约 2,728 字；12 分钟精读。

### [27 · 求职准备、系统设计与持续进阶](/chapters/27)

用可复现的工程证据证明能力，并围绕目标岗位补深度。

重点：面试、简历、系统设计、职业。约 3,057 字；14 分钟精读。
